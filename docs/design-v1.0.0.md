## 1. 术语

| 术语 | 含义 |
|---|---|
| **collection** | 一组接口的集合，对应**一个 `.http` 文件** |
| **请求** | collection 里的一个接口，对应文件里一个 `###` 段落 |
| **`.http` 方式** | 看/写**源码**：现有浮层编辑器（高亮、折叠、▶ 发送；导航全在侧栏） |
| **`api` 方式** | 看/写**表单**：现有侧栏 + 方法/URL/Header/Body 控件 |
| **映射文件** | `wpa-workspace.json`，**侧栏的唯一数据源**：登记了哪些文件、挂哪个文件夹、什么顺序 |
| **挂载** | 打开一个 `.http` 文件，把它登记进映射。这是往侧栏加文件的**唯一**途径 |

两种方式**不是两套数据**，而是同一个文件的两种视图。因此「互相转换」不需要数据搬迁，只做**视图切换 + 定位**，天然无损。

## 2. 核心模型

```
<工作区>/                      ← 放映射文件的地方，默认 ~/apifox-polaris-api/
├── wpa-workspace.json        ← 侧栏映射：哪些文件、归哪个文件夹、什么顺序
├── 用户中心.http              ← collection = 文件
├── 订单.http                  ← collection = 文件
├── examples.http              ← 自带示例
├── http-client.env.json       ← 环境变量（沿用现状）
├── .gitignore                 ← 自动写入 `_history/`
└── _history/                  ← 调用历史，一个接口一个 jsonl
    ├── 用户中心/
    │   └── 登录.jsonl
    └── 订单/
```

- 文件即 collection，**文件名即 collection 名**（去掉 `.http`）。
- 段落即请求：`### @name 登录` 到下一个 `###` 之前。
- **目录树 = 映射文件的渲染（2026-11-20 二次收紧）**：侧栏只认 `wpa-workspace.json`，
  **一个目录都不扫**。登记过的文件才出现，顺序与文件夹归属也全来自它；
  上一版写的「不需要注册表、扫目录就是全部集合」和「首次全量登记 + 发现未登记」都作废。
- **打开 = 挂载**：`openPath` 读成功一个 `.http`，就把它追加进映射（已在映射里则跳过）。
  「＋ 挂载 .http」只是这个动作的按钮外观，没有第二条加文件的路径。
- 内容真源仍然是文件：映射**只记「路径 → 文件夹」，不记请求、不记名字、不记内容**。
  映射丢失的后果只有一个——文件从侧栏消失，文件本身与内容不受影响；再打开一次就重新挂上。
- 映射文件同目录内的路径写**相对路径**（跟着仓库走）；其它位置一律绝对路径，UI 上标「外部」。
- 映射指向的文件不存在 → 显示灰色「找不到」+ 重新定位，**不静默删除**。
- 侧栏是唯一导航：`.http` 浮层里的文件树（S2.5c）与接口一览（S7.5）都已删除，浮层只剩源码；浮层开着时点侧栏接口 / 切 tab，源码跟随跳行。
- `host.storage` 里的 `collections` JSON 退役，只留偏好（浮层位置、字号、上次打开的文件、资源目录）。
- **身份写在文件里**：`# @file_id`（collection）/ `# @interface_id`（请求），都是普通注释，插件只在首次发请求时插入一次，之后不改写、不拦改。详见第 3 节与 13.3。

### 2.1 侧栏映射 `wpa-workspace.json`

```json
{
  "version": 1,
  "folders": [
    { "name": "订单服务", "collapsed": false, "files": ["orders.http", "D:////work////pay.http"] },
    { "name": "用户中心", "collapsed": false, "files": ["users.http"] }
  ],
  "unfiled": ["examples.http"]
}
```

| 字段 | 含义 |
|---|---|
| `folders[]` | 侧栏顶层文件夹，**数组顺序即显示顺序** |
| `folders[].files[]` | 该文件夹下的文件，**数组顺序即显示顺序**；相对路径相对映射文件所在目录 |
| `unfiled[]` | 直接挂在根上的散文件 |
| `collapsed` | 折叠态，纯 UI，丢了不影响内容 |

不做多层嵌套（第一版）：文件夹只有一层，文件直接挂在文件夹里。
拖拽的语义因此变成「把文件拖进文件夹 / 调顺序」——比跨文件搬段简单得多，也顺手解决了 S1.5 暂停的那个坑。

## 3. 文件格式（沿用 IDEA .http 语法，不发明 DSL）

```http
# @file_id c7f3a1b2  wpa 文件身份，用于关联本 collection 的历史目录
# @collection 用户中心          ← 可选，仅作说明；名称以文件名为准
@baseUrl = https://api.example.com
@token = {{$guid}}

### @name 登录
# @interface_id a1b2c3d4  wpa 接口身份，用于关联调用历史
POST {{baseUrl}}/login
Content-Type: application/json

{"username":"demo","password":"123456"}

### @name 查询用户
GET {{baseUrl}}/users/7?with=orders
Authorization: Bearer {{token}}
```

两条身份注释的规则：

| 项 | `# @file_id` | `# @interface_id` |
|---|---|---|
| 位置 | **必须在第一个 `###` 之前**（否则会被归进第一段） | `###` 标题行的**紧下一行** |
| 作用域 | 整个 collection（对应 `_history/<collection>/` 目录） | 单个接口（对应 `<接口>.jsonl`） |
| 何时写入 | 该 collection 第一次发请求时插入一次 | 该接口第一次发请求时插入一次 |
| 之后 | **插件永不改写**；用户可改可删，改了即换身份 | 同左 |
| 解析 | `^#\s*@file[_-]id\s+([A-Za-z0-9_-]{4,32})`，行尾文字一律丢弃 | `^#\s*@interface[_-]id\s+([A-Za-z0-9_-]{4,32})`，同上 |

两条都是**普通 `#` 注释**，IDEA / VS Code 当注释处理，不影响发送；命名沿用 IDEA 的 `# @name` / `# @no-redirect` 风格，解析时下划线与短横线都接受。

### 3.1 注释分级与配色（编辑器内）

| 级别 | 例子 | 样式 |
|---|---|---|
| **插件身份行** | `# @file_id …`、`# @interface_id …` | **紫色 · 斜体 · 加粗**，浅色主题 `#7c3aed` / 深色 `#a78bfa`；整行底色 `rgba(124,58,237,.06)`，左侧 2px 紫竖线；行号栏显示 `⌗` 锚点 |
| 请求元信息 | `# @name 登录`、`# @timeout 5000` | 同色系**斜体不加粗**（不与身份行抢注意力） |
| 行尾说明文字 | 身份行 `a1b2c3d4` 之后那半句 | 同色但 `opacity .55`、不加粗，视觉上让 id 值是主角 |
| 普通注释 | `# 这是随便写的` | 灰色斜体（现状，不变） |

配色只在**插件内的编辑器**生效，不改文件内容；用户用 IDEA 打开就是普通注释的灰色，不影响任何语义。

字段映射（双向、可逆）：

| api 方式字段 | `.http` 里的表达 | 反解方式 |
|---|---|---|
| collection 名 | 文件名 | 文件名 |
| collection 身份 | 首行 `# @file_id xxx` | 文件头注释（缺失则按需补） |
| 请求身份 | 段首第二行 `# @interface_id xxx` | 段内注释（缺失则按需补） |
| 请求名 | `### @name 登录` | 段首标题 |
| method + url | 请求行 `POST {{baseUrl}}/login` | 请求行 |
| params 表格 | 拼进 URL 查询串 | 解析 URL 查询串回填表格 |
| headers 表格 | 逐行 `K: V` | Header 行 |
| bodyType=json / text | 空行后的原文 | `Content-Type` 判定 |
| bodyType=form | `Content-Type: application/x-www-form-urlencoded` + `a=1&b=2` | 同上 |
| bodyType=multipart | `--boundary` 分段，段内 `< 文件路径` 表示二进制附件 | 同上（现有解析器已支持） |
| 环境变量 | `http-client.env.json` | 沿用现状 |

**保真原则**：解析器遇到不认识的语法（脚本块、`><` 断言、自定义注释）**原样保留**，绝不因为「UI 不认识」就把用户的写法删掉。

## 4. 双视图跳转

| 方向 | 入口 | 行为 |
|---|---|---|
| api → .http | 请求 tab 右上角「`</>` 源码」 | 打开（或复用）该文件的浮层，滚到该请求首行，选中整段，闪一下高亮 |
| .http → api | 请求左侧 ▶ 旁的「表单」图标 | 切到该请求的 api tab；没开过就新建，定位到对应 collection + 请求 |
| 侧栏 → 任一 | 侧栏 collection 右键菜单 | 「用源码打开」「用表单打开」 |

定位靠解析器已给出的 `request.line`（段首行号），不需要额外索引。

游标同步：浮层里光标落在哪一段，侧栏对应请求就高亮；反过来也一样。两边都指向 `{file, requestName}` 这一个游标。

## 5. 写回策略（关键，决定会不会把用户文件写乱）

- **段落级替换，不是整文件重写**。改一个请求 = 只替换「该 `###` 行 → 下一 `###` 前」这段字节，其余原样保留（注释、空行、排版、其它段的手写格式都不动）。
- 新增请求 = 文件末尾追加一段；删除 = 删掉该段及其后一个空行；拖拽排序 = 整段搬移。
- 写入前比对文件 `mtime`：与内存里的基线不一致，说明**外部改过**，弹三选一「重新载入 / 用我的覆盖 / 另存为新文件」，不静默覆盖。
- 连续编辑合并写：400ms debounce，避免边打字边写盘。
- 写失败（权限、路径不存在）→ 状态栏红字 + 保留内存改动，不丢数据。

## 6. 旧数据迁移（一次性）

启动时若 `host.storage` 里还有旧 `collections` 且未迁移：

1. 每个分组写成 `<分组名>.http`（重名加 `-2`，非法字符 `\/:*?"<>|` → `_`）；
2. 每个请求按第 3 节序列化，params 拼进 URL；
3. 原 JSON 导出到 `~/apifox-polaris-api/_migrated-collections.json` 作备份；
4. storage 里清掉 `collections`，写入 `migrated.v1 = true`。

迁移本身幂等：中途失败可重跑，已存在的文件不覆盖（走 `-2` 命名）。

## 7. 浮层拖拽

- 状态：`pos = {mode: 'edge' | 'free', top, left}`；默认 `edge`（贴右缘，与现在一致）。
- 热区：浮层顶部标题条 + 空白区（不含按钮、tab、文本区）。
- 拖动：抓取点偏移跟手，`pointermove` 里只改 transform，`requestAnimationFrame` 合帧。
- 吸附：距左右边缘 < 24px 时回到 `edge` 模式；拖出窗口外自动夹回可视区。
- 双击标题条：复位右缘默认位置。位置持久化到 `ui.float`。
- 与右缘箭头联动：浮层收起后箭头出现在浮层当前高度，不再固定居中。

## 8. 字号缩放

- `Ctrl` + 滚轮在编辑器文本区：12–28px，步进 1px；只在 `{passive:false}` 监听里处理，不劫持普通滚动。
- 实现用 CSS 变量 `--pa-fs`，textarea、行号层、高亮层共用一份 —— 三层同字号才不会错位。
- 角落气泡提示「字号 18px」，800ms 自动消失；`Ctrl+0` 复位 14px。
- 持久化到 `ui.fs`，只影响 `.http` 编辑器，不改宿主界面。

## 12. api 方式体验盘点（v1.0.0 一并处理）

### 12.1 基线：现在已经有的（不用重做）

多 tab（重命名 / 关闭其他 / 关闭左右）、侧栏 collection + 搜索、Params 表格与 URL 双向同步、Headers 表格（可勾选启用）、Body 五型（无 / JSON / 文本 / Form / multipart 文件）、JSON 格式化、环境变量（baseUrl + 变量表）、全局超时、发送与逻辑中断、响应五视图（原始 / 对象树 / 表格 / 预览 / 响应头）、路径下钻 + 过滤、表格列宽/隐藏/排序、复制/下载响应、cURL 导入与导出、布局横竖切换、`Ctrl+Enter` 发送 / `Ctrl+S` 保存。

### 12.2 文件化之后立刻打架的三处（不修就出 bug）

| # | 问题 | 现状 | 1.0.0 做法 |
|---|---|---|---|
| 1 | **环境变量有两套** | api 侧存在 `host.storage` 的 `envs`；`.http` 编辑器读 `http-client.env.json`。同一个文件两个视图，变量值可能不同 | 只认 `http-client.env.json`（+ private）。api 侧「环境管理」变成这个文件的可视化编辑器，读写同一份；storage 只留「当前选中的环境名」 |
| 2 | **文件头 `@var` 在表单视图看不见** | `.http` 里的 `@baseUrl=…` 只有源码视图能改，表单视图用不了这些变量 | 请求编辑区加第 4 个子页「变量」，直接编辑文件头变量；与源码视图同一个真源 |
| 3 | **未解析变量静默发出** | 变量不存在时 `{{token}}` 原样发出去，服务端返回 401 才回头查 | 输入 `{{` 弹补全（文件变量 / 环境变量 / `{{$guid}}` 等内置）；未解析的变量在发送前红字列出，可「仍然发送」 |

### 12.3 构造能力的缺口（对标 Postman / IDEA 的最低集）

| # | 缺什么 | 用户现在的绕法 | 1.0.0 做法 |
|---|---|---|---|
| 4 ✅ | **multipart 表单上传**（S8.1 已落地） | 以前只能去 `.http` 里手写 boundary 分段，表单视图完全没有入口 | Body 第 5 型「文件」：一行一个字段，第三列选「文本 / 文件」；文件格点一下弹系统对话框，只显示 basename、存路径；内部序列化成 `.http` 的 boundary 分段，切到「文本」看到的就是同一段文字 |
| 5 | **Auth 面板** | 手抄 `Authorization: Bearer xxx` | Bearer / Basic / API Key 三种，填完写进 Headers 表（文件里仍是普通 Header，纯文本可读、不引入私有语法） |
| 6 | **collection 级默认值** | 每个请求重复抄同一个 baseUrl、同一个 token | 文件头变量 + collection 级默认 Headers（`# @collection.header K: V`），请求可单独覆盖；表单里显示「继承自 collection」灰字 |
| 7 | **请求级设置** | 超时只能全局改；跳转重定向、跳过 TLS 校验没得选 | 请求头注释 `# @timeout 30000`、`# @no-redirect`、`# @insecure`，表单里做成三个控件，源码视图同样可读 |
| 8 | **批量编辑** | Header / Params 一行行点加号 | 表格右上加「文本模式」：整段 `K: V` 多行文本 ↔ 表格互转，一次粘贴一片 |
| 9 | **复制请求** | 手动新建再抄一遍 | tab 右键与侧栏右键加「复制为副本」，文件名段名自动加 `-copy` |
| 10 | **导入** | 只有粘贴 cURL 文本 | 支持导入 `OpenAPI 3 (json/yaml)` 与 `Postman v2.1`，一个文件生成一个 collection 的 `.http` |
| 11 | **Cookie / 登录态** | sidecar 每次新建 client，Cookie 不保留；只能手动复制 token 当 Header | sidecar 进程内共享 cookie jar（reqwest `cookie_store`），登录一次后续请求自动带；设置里可查看、清空 |

### 12.5 范围建议

- **1.0.0 必做**（文件化 + 一致性 + 硬缺口）：第 1–9、12、15 项。这些不做，「文件化」就只是个存储替换，体验没提升。
- **1.0.1 跟进**：第 10（导入）、11（Cookie）、13（CSV）、14（历史）、16、17。理由：10 和 11 要动解析器与后端依赖，风险独立，适合单独一版验证。
- **不做**：预请求脚本 / 断言执行、响应 Diff、耗时分解（DNS/TCP/TLS）、WebSocket / gRPC、团队共享 —— 与「本地 .http 文件工具」的定位不符，先把主线做扎实。

## 13. 历史存储与「取消」（定稿）

### 13.1 300 接口会不会卡：卡的不是 JSON，是「一次读多少」

| 对象 | 结论 |
|---|---|
| **集合数据**（300 个接口定义） | 不是"会不会卡"，是**存不下**：单请求约 1.5–2 KB，300 个约 **0.5–0.7 MB**，而 `host.storage` 单值上限 **256 KiB**，约 **100–150 个就触顶**。文件化是硬约束，不是优化项。 |
| **历史记录** | JSON 本身没问题。问题是现有 `http/listResults` **每次把目录里所有 json 全文读出 + 逐个 parse**，而且只保留最新 300 条——300 接口场景下大半接口的历史压根不出现，功能已失效。 |

按新布局重算（300 接口 × 10 次，全字段存）：

| 指标 | 数值 |
|---|---|
| 单条（典型 REST，响应 3–30 KB） | 5–40 KB，平均按 20 KB |
| 单文件（10 条） | 约 200 KB |
| 全量磁盘 | 约 **60 MB**（300 个文件） |
| 打开历史面板 | 只读该接口那 1 个文件 → **5–15 ms** |
| 打开 collection 概览 | 读目录列表 + 每文件首尾各一小段 → 30–80 ms |

结论：**按接口读，全存也不卡**。

### 13.2 布局：一个接口一个 jsonl（定稿）

```
~/.apifox-polaris-api/
├── 用户中心.http                  ← collection = 一个 .http 文件（不目录化）
├── 订单.http
├── .gitignore                     ← 首次创建时自动写入 `_history/`
└── _history/
    ├── 用户中心/
    │   ├── 登录.jsonl             ← 一行一次调用，只留最近 10 行
    │   ├── 查询用户.jsonl
    │   └── 登录/
    │       └── 2026-11-20T12-56-01-a1b2.bin   ← 仅二进制响应才外置
    └── 订单/
        └── 创建订单.jsonl
```

- 目录名 = collection 的**文件名 stem**（人可读，中文保留）；改名时靠文件内 `@file_id` 认出"同一 collection"，自动 `rename` 目录；
- 接口文件名 = 接口名，禁字符 `\/:*?"<>|` → `_`，重名加 `-2`（同文件内）；
- 保留最近 **10** 条：追加第 11 条时**重写文件取后 10 行**，tmp + `rename` 原子替换（单文件 200 KB 级，代价可忽略）；
- 接口删除：历史目录保留 7 天后清理；设置里可「立即清理」。

### 13.3 身份：`@file_id` / `@interface_id`（定稿）

**为什么不用段落序号**：序号会漂移，而且是静默漂。

| 操作 | 用序号当键的后果 |
|---|---|
| 在 A 前插入 D | 「第 1 段的历史」变成 D 的，其实是 A 的 |
| 删掉 B（A、B、C → A、C） | C 从第 3 段变第 2 段，查到的是 B 的历史，且看不出错 |
| 两个接口上下调换 | 两条历史直接互换 |

所以身份写进文件，用注释承载（见第 3 节格式与配色规则）：

```http
# @file_id c7f3a1b2  wpa 文件身份，用于关联本 collection 的历史目录
### @name 登录
# @interface_id a1b2c3d4  wpa 接口身份，用于关联调用历史
```

**定位是"提示"，不是"锁"**：

| 项 | 行为 |
|---|---|
| 写入时机 | 只在「要落历史」的那一刻写，详见 13.3.1；只打开文件不写 |
| 之后 | 插件**永不主动改写**，也不拦截编辑；可改、可删、可手抄 |
| 改成新值 | 视为新身份 → 历史面板「暂无调用记录」 |
| 删掉 | 下次发请求补一个新 id → 同样断链 |
| 改回原值 | 历史立刻回来（id 就是键） |
| 段落复制到本文件别处 | id 同文件内重复 → 后一个换新 id 并提示一次 |
| 复制到别的 .http | 无影响，历史按 collection 分开存 |
| 文件只读 / 无写权限 | 不写 id，**本次也不记历史**（见 13.3.1） |
| 设置开关 | 「自动标记接口身份」默认开；关闭后不写任何注释，降级为「名称 + 方法 + URL」指纹匹配，改名/改地址后会断链 |

**唯一的主动提示是询问，不是拦阻**：某段没有 id（或 id 是新的）但指纹与历史里某个旧 id 吻合时，历史面板顶部显示一行——

> 这段看起来是原来的「登录」（12 条记录）。要接回它们的身份吗？　`接回` ／ `当作新接口`

不点它就是新接口；点了写回旧 id。**改 id 不会丢东西，也不会被阻止。**

#### 13.3.1 赋予时机（逐场景定死）

总原则：**只有「要落一条历史」时才写身份，且先写身份、后写历史。**

| 场景 | `@file_id` | `@interface_id` | 说明 |
|---|---|---|---|
| 打开 / 扫描文件 | 不写 | 不写 | 看一眼不该让 git 多出 diff |
| 首次发送并拿到结果 | 缺则插到**文件第 1 行**（第一个 `###` 之前） | 缺则插到 `###` 紧下一行 | 两条一起插，**一次写回** |
| 请求前变量未解析、请求没发出 | 不写 | 不写 | 根本没调用过 |
| 请求失败（超时 / DNS / 4xx / 5xx） | 照写 | 照写 | 失败也是历史，`error` 记原因 |
| 文件只读 / 无写权限 | 不写 | 不写 | **本次不记历史**：宁可不记，也不产出对不上的孤儿 |
| 关闭「自动标记接口身份」 | 不写 | 不写 | 降级为指纹匹配 |
| 同文件两个窗口同时首调 | 插入前重读 + 指纹查重 | 同左 | 已有则不重复插 |
| 迁移旧 JSON | 不预置 | 不预置 | 等首次调用 |
| `examples.http` | 同规则 | 同规则 | 示例也是可编辑的活文件 |

**写盘顺序**（这决定了历史里有没有身份）：

1. 先插 id，**等写盘成功**；
2. 再追加历史行（行里带 `fileId` / `interfaceId`）；
3. 第 1 步失败（只读、被锁、mtime 冲突重试 2 次仍失败）→ **不写历史**，状态栏提示一次「该文件不可写，本次未记录历史」。

**并发写回**：插 id 前读 mtime，写回时 mtime 已变就重读文件、按「`###` 标题 + 该段内容指纹」重新定位段落再试——**不能用行号定位**，因为插入一行会让后面所有行号整体下移。

### 13.4 一条历史存什么（全存）

| 字段 | 内容 |
|---|---|
| `ts` | 发出时间，ISO 8601 带毫秒 |
| `method` / `url` | 实际发出的方法与地址（变量已展开） |
| `templateUrl` | 未展开的原始模板（反查用） |
| `req.query` / `req.headers` / `req.body` | 请求参数、请求头、请求体（含 `contentType`） |
| `res.status` / `res.headers` / `res.body` | 状态码、响应头、响应体 |
| `res.sse` | SSE 场景：事件流原文 + `truncated` |
| `durationMs` / `ttfbMs` | 耗时 / 首字节（有则记） |
| `name` / `fileId` / `interfaceId` | 当时的接口名与两级身份（文件自证，外部改名也能反查） |

### 13.5 全存的三条护栏

1. **二进制外置**：`image/*`、`audio/*`、`application/octet-stream`、zip 等不进 jsonl（base64 会膨胀 33%，还把单行撑爆），落到 `_history/<collection>/<接口>/<ts>.bin` 原字节，jsonl 记 `bodyRef` + `size` + `mime`。反而能预览、能播放。
2. **单条上限**：默认 10 MB；超出记 `truncated: true` + 前 64 KB 预览，完整字节仍落 `.bin`（不丢，只是不进 jsonl）。设置可放开。
3. **不进 git**：首次创建 `_history/` 时在资源目录写 `.gitignore`（只追加 `_history/`，不动用户已有内容），否则几十 MB 历史会把仓库撑爆。

### 13.6 「取消」做成哪一档

现在的「停止」只是逻辑中断：`invoke` 是同步 RPC，取消只让 UI 丢弃迟到响应，**sidecar 里请求还在跑**（大文件会一直占带宽到结束）。三档可选，成本差一个数量级：

| 档 | 做法 | 能中断什么 | 成本 |
|---|---|---|---|
| **L0 假装取消**（现状） | UI 丢弃响应 | 什么都不能。下载 100 MB 仍会跑完 | 0 |
| **L1 标志位 + 流式读**（推荐，进 1.0.0） | UI 写 `_cancel/<requestId>.flag`；sidecar 把响应体从「一次读全」改成**分块读**，每 64 KB 检查一次该文件，命中就 `drop` 连接 | 大响应的下载中段（最常见痛点）；SSE 天然支持 | 约 60 行 |
| **L2 async 化** | `reqwest::blocking` → async + tokio runtime，`http/cancel` 走 `join_handle.abort()` | 一切，包括卡在 TTFB / 连接阶段的请求 | 全链路重写，独立里程碑 M6 |

**L1 为什么够用**：真实场景里"点了停止却还在跑"几乎都是下载/大响应（几 MB 的 JSON、文件、SSE 流），这些都能在分块循环里被打断；真正难中断的是"服务端迟迟不返回响应头"，这属于超时该管的事（现有全局超时 + 每请求 `# @timeout` 已覆盖）。

**L1 的关键设计**：取消标志用**文件**而不是 RPC，因为请求进行中这个 handler 还没返回，同一条 RPC 通道上再发 `http/cancel` 可能排队进不来（取决于 SDK 是否并发处理，不该赌）。文件标志不依赖 RPC 并发，任何情况下都能生效；检查频率 64 KB 一次，一次 `stat` 在 Windows 上是微秒级，开销可忽略。

L2 留到"确实需要中断连接阶段"时再做，先不排期。

### 13.7 还剩两个可选项

1. **保留条数**：默认 10，设置里给 3 / 10 / 30 三档？
2. **二进制是否全量落盘**：全量（可能被视频下载吃磁盘）还是设上限（如 5 MB，超出只留首尾各 1 MB）？我倾向后者。

## 14. 示例文件（examples.http）的注释规范

示例不只是"能跑的请求"，它是**第一份教程**——用户装完插件第一眼就看它。所以每个请求段落都要带说明，但**不能变成文档墙**：每段最多 2 行导语，讲"这节演示什么 + 一个最容易踩的点"。

三类注释分工：

| 类型 | 写法 | 作用 |
|---|---|---|
| **章节导语** | `### 2. POST JSON（OpenAI 兼容对话体）` 下一行 `# 演示：JSON body、Content-Type、{{变量}} 的插值` | 让人秒懂这节在教什么 |
| **踩坑提示** | `# 注意：body 与 header 之间必须有一个空行，否则 body 会被当成 header` | 只在真有坑的地方写 |
| **身份说明**（仅第一节） | 见下 | 解释 `@interface_id` 是什么、能不能改 |

**身份说明只在第一节写一次**，不每段重复：

```http
### 1. GET 查询串与鉴权头
# 演示：查询参数、Authorization 头、{{baseUrl}} 变量
# 首次发送后，插件会在标题下自动加一行 `# @interface_id …`（紫色斜体），用来把调用历史对到这个接口。
# 它是普通注释，可以改也可以删；改了等于换身份，旧历史不会跟过来，但可以在历史面板一键接回。
GET {{baseUrl}}/get?hello=world&lang=zh
```

**示例里不预置任何 id**：`@file_id` / `@interface_id` 一律由"第一次发请求"生成。原因有两条——预置会让每个用户看到一串来历不明的字符；而示例文件被改写在预期之内（它本来就是可编辑的活文件）。

**实现注意**：
- 加注释会改变 `ui/sample-http.js` 的源码文本，README 里那段 `http` 代码块由 `tools/sync-readme-sample.mjs` 从源码生成，改完必须跑一次同步，否则 `sample.test.mjs` 里"README 与源码一字不差"的断言会红；
- 注释会一起同步进 README，所以**控制总量**：9 节 × 2 行 ≈ 18 行，可接受；别写成每节 5 行。
- 注释里不出现 `#` 以外的特殊标记（避免被别的 `.http` 实现误解析）。

## 15. 两套 demo 必须同源

**现状是两套**：pa 原本在 `ui/app.js` 的 `seed()` 里内建一套「api 形式」demo（环境 `Demo · jsonplaceholder` + collection `示例 · DEMO` 的 5 个请求，存在 `host.storage` 的 JSON 里）；我们又做了 `examples.http`（8 节，存在磁盘，将扩到 9 节）。文件化之后如果两者都留着，就是**两个 demo、两套地址、两份维护**——这正是要避免的。

**结论：能同源，而且同源是文件化白送的**——demo 就是磁盘上的一个 `.http` 文件，api 视图和源码视图读的是同一份。所以：

1. **`seed()` 退役**：不再往 storage 写任何 collection / env；
2. 首次启动在资源目录生成 `examples.http` 与 `http-client.env.json`（baseUrl 一项）。**文件名沿用 `examples.http`**（0.6.2 已落地，改名只会让老用户的文件凭空多一份），界面文案叫「示例」；
3. 老 demo 的 5 个请求逐个处理：

| 老 demo 请求 | 去留 | 理由 |
|---|---|---|
| `GET /users`（用户列表） | **合并**进第 1 节 | 与新的 GET 节重复，取新的 |
| `GET /todos/1`（单个对象） | 丢弃 | 第 1 节 `GET /get` 的 JSON 响应已覆盖「对象树」视图 |
| `GET /users/1` | 丢弃 | 与上面重复 |
| `GET /albums`（嵌套数组 → 表格） | **保留为新的一节**（第 9 节） | 演示「表格视图 + 路径下钻」，现有 8 节里没有替代 |
| `POST /posts`（JSON body + Bearer） | **合并**进第 2 节 | 新的 POST 节已覆盖，且带跨请求引用 |

所以示例从 8 节变 **9 节**：原 8 节 + 「数组响应 → 表格视图」1 节。

4. 老 demo 里的假 token `demo-token-123` 从环境挪到 `examples.http` 文件头的 `@token`，环境文件只留 baseUrl —— 与 12.2「环境只认 `http-client.env.json`」一致；
5. **老用户升级**：storage 里已有的 collection 走第 6 节迁移，落成 `示例 · DEMO.http` 保留在原处（不删用户数据），首次打开时提示一次「示例已更新，是否用新版 demo 替换？保留 / 替换 / 别再问」。

**地址定案**（3 个域名，每个都在注释里写明用途）：

| 域名 | 用途 |
|---|---|
| `https://httpbin.org` | 常规请求（`/get` `/post` `/json` `/anything`） |
| `https://httpbingo.org` | SSE（`/sse?count=3`），httpbin 的 SSE 端点不稳 |
| `https://jsonplaceholder.typicode.com` | 仅 1 节，演示数组 → 表格视图；注释标注「访问慢可跳过」 |

不做第 4 个域名，也不依赖登录态，任何一节都能在装完插件 30 秒内跑通。

## 16. 历史怎么查看（对齐使用习惯）

**现状的毛病**：历史挤在「.http 工作区」浮层里的第二个 tab，是一个**全局扁平列表**——所有接口的结果混在一起按时间排。后果是 300 接口时根本找不到"我这个接口调过什么"，而且看历史必须先离开当前请求去开一个浮层。

**入口按"你在哪"来放**：

| 入口 | 场景 |
|---|---|
| **请求 tab 里第 5 个子页「历史」**（与 Params / Headers / Body / 变量 并列） | 主入口：正在调这个接口，顺手看它调过几次 |
| 侧栏接口右键「查看历史」 | 从树里直接跳到某个接口的历史 |
| 顶部「调用历史」（原「历史结果」，1.0.1 扩成跨 collection 检索） | 找"昨天那个 500 是哪个接口" |

**请求内历史面板的样子**：

```
最近 10 次 · 成功 7 · 失败 3 · 平均 142ms        ← 失败数标红
─────────────────────────────────────────────
▸ 3 分钟前   200  142ms  12.4 KB   ← 最上面是最新
▸ 1 小时前   500  1.2s   2.1 KB   ⚠ 服务端错误      ← 失败行左侧红竖线
▸ 昨天 18:02 超时 30s    —        ⚠ 连接超时
```

点开一条 → 上下两块：**请求**（方法/URL/参数/头/体）、**响应**（状态/头/体，SSE 看事件流原文），底部三个操作：

| 操作 | 作用 |
|---|---|
| **填入当前请求** | 把这条历史的参数/头/体拉回编辑器，当草稿改——最符合直觉的"复用"，比"复制 cURL"顺手 |
| 复制响应 / 下载 | 沿用现有响应区能力 |
| 删除这条 | 只删这一行，其余保留 |

**侧栏状态点**：接口名右侧一个小圆点，最近一次成功=绿、失败=红、无记录=不显示。这条最省事——不点进去就知道哪个接口坏了。

**明确不做**（留 1.0.1）：两次调用 diff、跨接口统计图表、按状态码/耗时筛选。1.0.0 只保证「找得到、看得清、能复用」。

**一个大前提**：历史面板**只读**，任何操作都不会自动覆盖你正在编辑的请求（"填入当前请求"必须你点，且有未保存改动时先确认）。
